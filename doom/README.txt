UniDoom v0.1 — Mini first-person sector demo for Sharp MZ-800 + UniCard
====================================================================

Load unidoom_v0_1.mzf with your usual Sharp MZF loader.
Explore a small sci-fi sector, shoot the security drones, collect the blue
data core in the northeast room, then return to the green exit in the
southwest corner. Press M for the map or P for a guided play-through.

The complete level, textures, sprites, renderer and game logic are embedded
in the MZF. No WAD or other data files are required. All art is original
procedural pixel art generated by the included Python build tool.

Requires Sharp MZ-800 320x200 / 16-colour graphics with 32 KB video RAM and
UniCard MK3b firmware supporting the original OpenCPU interface. Code, state
and framebuffer stay in the 64 KB SRAM window 20020000h..2002ffffh.

CONTROLS

  UP / W          Walk forward
  DOWN / S        Walk backward
  LEFT / A        Turn left
  RIGHT / D       Turn right
  Q / E           Strafe left / right
  SPACE           Fire; hold for repeated shots
  F               Open / close the nearest door, within reach
  M               Toggle the minimap
  P               Start / stop the guided tour
  L               Toggle the central light cone
  Z               Toggle running
  R / ESC         Restart the level

Walking, turning, strafing and firing can be combined. The Z80 reads the
entire keyboard matrix at 50 Hz, producing both a latched event byte and a
held-button bitmask. Short taps are retained through frame transfers.
Movement keys take control from the guided tour. Starting the tour begins
a fresh level; stopping it leaves the camera where it currently stands.

The map marks walls, yellow closed doors, green open doors/exit, red live
drones, the cyan core, and your white position marker. The HUD shows health,
ammo, disabled drones, and whether the core has been collected.

Security drones take two direct hits. They can damage you when nearby and
visible, so use walls and doors for cover. The medkit restores 25 health.
The objective is to recover the core and reach the exit; clearing every
drone is optional. Empty ammo or a lost signal can be reset with R.

Doors rise over 16 simulation frames. The opening exposes the room behind
it from the bottom upward, including partially visible sprites. The player
can pass when sufficiently open. A door will stay open around the player
instead of closing through them.

RENDERING AND HARNESS

The UniCard ARM routine performs all rendering and simulation:
  - 160 grid DDA rays with perpendicular depth, giving a 90-degree field of view
  - 16x16 tiled metal, brick, hazard, reactor, door and exit wall textures
  - Perspective textured floor and ceiling with distance lighting
  - Two independently animated doors, layered over the scene behind them
  - Transparent 32x32 billboard drones, data core and medkit
  - Per-column wall depth and per-door vertical clipping for sprite occlusion
  - Camera-depth sprite ordering, hitscan, radius collision and wall sliding
  - A procedural weapon view, muzzle flash, hit flashes, HUD and minimap
  - A deterministic guided route through the actual movement/collision rules

The scene viewport is 160x160 samples written as doubled horizontal pixels
inside a 320x160 area. UI text and the weapon use the physical 320-pixel
resolution. The framebuffer is still four 8192-byte Sharp bitplanes.
The demo uses a grid-based 2.5D world with equal-height orthogonal walls.
Physics advances once per rendered frame; speed on hardware depends on the
UniCard and the Z80's complete 32 KB video transfer.

The host retains the existing ports 50h/51h and commands CAh..CEh, byte-for-
byte upload verification, bounded busy polling, IM2 keyboard IRQ and GDG
plane transfer. The direct MZF load/execute address remains 3000h.

OpenCPU ABI:
  20020000h     Callable Thumb entry pointer
  20020004h     Framebuffer pointer, 20028000h
  20020008h     Latched key event
  20020009h     Native initialization flag
  2002000ah     Held button mask (written separately to preserve +09h)
  2002000bh     Reserved

Held bits:
  01h forward, 02h backward, 04h turn left, 08h turn right,
  10h strafe left, 20h strafe right, 40h fire, 80h use door.

The first native call initializes all live game state, even with dirty SRAM.
The linker rejects code/state overlapping the framebuffer. A red border and
stopped host indicate upload verification failure or native busy timeout.

BUILD

From the workspace or package root:
  python3 doom/tools/build.py
From the repository root:
  make doom
Or from the doom directory:
  make

Tools: Python 3, clang with ARM target, lld, llvm-objcopy and pasmo.
UNIDOOM_LLD may specify a linker path outside PATH.

The asset generator uses only Python's standard library. It checks the
closed map boundary, legal spawn positions and a reachable guided route.
The shared ../common/key_table.bin provides the 80-byte keyboard mapping.
The original demo executable is not required.
Output is unidoom_v0_1.mzf in the parent directory. The build subdirectory
contains the native image/ELF/map, Z80 binary/symbols, level manifest and hashes.
These products are ignored by Git. make clean removes them and Python
caches; make package creates the verified source/release ZIP using the
shared ../tools/package.py. Releases and previews are retained by clean.

VERIFY

Additional dependencies: Unicorn 2.1+, numpy, Pillow and libz80ex.so.1.
  python3 doom/tools/verify.py
From the repository root:
  make verify-doom

UNIDOOM_Z80EX may specify a Z80 library path. Install Python verification
dependencies from ../requirements-dev.txt into your Python environment.

Verification includes:
  - Actual assembled Z80 host and Cortex-M4 code across 60 frames
  - Exact framebuffer/game-state/position comparison with native C
  - Simultaneous keys, held walking/autofire and preserved short key taps
  - All door opening phases, walking through and safe closing
  - Independent ray-versus-map-cell box intersections for eight views
  - Closed, partially open and fully open door/sprite occlusion
  - Radius collision and blocked movement near a pillar
  - Closed-door shot blocking and destruction of an exposed drone
  - Core collection, return-to-exit objective and reset
  - A complete 360-frame guided tour without teleporting or crossing walls
  - SRAM guards, framebuffer padding, upload failure and busy timeout

The CPU code and modeled protocol are verified. Physical UniCard/Sharp
hardware and electrical timing have not been tested. No frame-rate claim
is made for the native-rendered preview animation.
